# Frontend build inputs

The versioned `solovey.frontend-build-inputs/v1` projection is generated by Product tooling. It declares the immutable UI source used by this single Classic+Nexus application; it is not a runtime ComponentHost manifest or a component permission authority.

Product owns `components/sources.lock.json`, Go module resolution and source acceptance. `node scripts/frontend-build-inputs.mjs prepare` reuses that acceptance, verifies the full external source trees, and projects only each declared `component.json`, `frontend/**` closure and external `HOST_UI_PIN.json`. Product-owned UI contributions receive content hashes and an exact projected Git tree as well. No source version or editable lock is maintained separately.

The projection is generated inside `frontend/.component-inputs/`. Its `manifest.json` includes the unchanged source lock, its canonical digest, component IDs, file hashes, projected trees, and hashes of the existing public UI exports and locked toolchain inputs. Product supplies the manifest SHA256 through `SOLOVEY_UI_INPUTS_SHA256`. A standalone consumer must receive that digest from its trusted build invocation along with the prepared directory. Recomputing a digest of untrusted input does not establish provenance.

`node frontend/scripts/component-build-inputs.mjs verify` validates this exact directory and caller-supplied digest without resolving Go modules, discovering Product parents, downloading code or falling back to sibling sources. It rejects missing/extra files, symlinks, wrong IDs or trees, schema drift, source-lock mismatch and public API/toolchain drift. Existing source integrity algorithms are shared with Product rather than independently reimplemented.

Vite, TypeScript, unit tests, locale/icon checks and component-owned browser scenarios consume only this directory. The Product adapter `node scripts/frontend.mjs <task>` prepares inputs and passes their accepted digest to npm. The frontend never calculates its own trust digest from an untrusted manifest. Core/minimal still verify supplied inputs before excluding optional entries. Product asset tooling recognizes the new projected manifest keys and explicitly supports previous qualified compiled asset keys for rollback; that bridge does not load previous source directories. Physical frontend repository extraction is outside this boundary.

The Product qualification command `node scripts/frontend-standalone.mjs --out <fresh-evidence-directory> [--previous-dist <accepted-dist>]` copies only tracked Frontend source into a private clean directory, supplies the accepted projection, and runs locked installation, typecheck, lint, units and Full/Core/minimal builds with Go/Git absent from PATH. It records source/input hashes, negative invocations, asset manifests and inverse/forward asset publication. CI runs this gate on Linux and Windows. Browser qualification also builds and serves the actual embedded production assets through the pinned Backend; the Product supplies the nested admin base in the existing HTML template.
